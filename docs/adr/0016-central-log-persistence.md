# ADR-0016: Hub 运行日志持久化与统一日志查询

- **Status:** Accepted
- **Date:** 2026-10-13
- **Deciders:** 维护者授权修复日志缺失并完善日志易用性与安全性
- **Scope:** pp-common 日志记录、pp-hub 持久化与查询、Agent 日志采集、管理 Web 日志页

## Context

系统日志页读取 system_logs，但 Hub tracing 只写控制台；只有少数定时任务显式写表。
Agent tracing 经 gRPC 写 agent_logs，集中日志页没有入口。查询失败时页面也显示为空态。

## Decision

Hub tracing 保留控制台输出，同时通过有界、非阻塞队列将应用 info/warn/error 记录写入既有
system_logs。数据库写入单独异步处理，过滤自身与数据库驱动日志以防回环，关闭时排空队列。
记录长度与队列容量有上限，溢出/写入失败在控制台提示，不以同步数据库写入阻塞请求线程。

Hub 与 Agent 的持久化/上报记录使用共享脱敏与限长逻辑；不采集 SQL、HTTP 调试正文或
敏感字段，脱敏常见认证令牌、密码和 URL 凭据模式；这不是对任意自由文本的完整敏感信息识别。控制台仍遵循原环境过滤配置。

GET /api/v1/logs 默认保留系统日志语义，增加 kind=agent 查询既有 agent_logs，支持级别、
来源与分页，延续 logs:read 权限。页面提供系统/Agent 切换、刷新与明确的错误状态。
不修改数据库 schema、不重写既有日志历史；原节点日志接口保留。

## Consequences

无需数据库迁移；新运行日志开始持久化，已有控制台历史不会自动回填。写库故障时应用
继续运行，日志持久化可能丢失且控制台可见；有限队列防止持续数据库故障耗尽内存。
日志留存仍由现有定时清理管理。日志权限与脱敏不能替代部署环境的访问控制和 HTTPS。
